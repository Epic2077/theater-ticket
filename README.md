# مصائب روزگار از دست رفته — وب‌سایت نمایش و رزرو بلیت

وب‌سایت تک‌صفحه‌ای و کاملاً راست‌به‌چپ (فارسی) برای معرفی یک اجرای صحنه‌ای و صدور بلیت دیجیتال، ساخته‌شده با **React + TypeScript + Vite** و CSS دست‌نویس (بدون فریم‌ورک UI).

## اجرا

```bash
npm install
npm run dev      # محیط توسعه — http://localhost:5173
npm run build    # خروجی production در dist/
npm run preview  # سرو کردن خروجی build
npx tsx scripts/smoke.ts   # آزمون منطق اعتبارسنجی، قیمت‌گذاری و تاریخ‌ها
```

## سفارشی‌سازی

| چه چیزی                                   | کجا                                                   |
| ----------------------------------------- | ----------------------------------------------------- |
| نام گروه، عنوان نمایش، متن‌ها، سالن، تماس | `src/config/theater.ts`                               |
| قیمت بلیت عادی/دانشجویی، سقف تعداد، واحد  | `src/config/pricing.ts`                               |
| تاریخ‌ها و سانس‌های اجرا                  | `src/data/performances.ts`                            |
| عوامل و بازیگران                          | `src/data/cast.ts`                                    |

- **تاریخ اجراها** به‌صورت خودکار از روی تقویم هفتگی در `performances.ts` ساخته می‌شوند
  (پنجشنبه و جمعه، ۴ هفته، دو سانس) تا هیچ‌وقت تاریخ گذشته نمایش داده نشود؛ برای تاریخ‌های ثابت،
  آرایهٔ `performances` را دستی مقداردهی کنید (`dateISO: 'YYYY-MM-DD'`).
- تاریخ‌ها با تقویم جلالی (`Intl.DateTimeFormat('fa-IR')`) نمایش داده می‌شوند ولی به‌صورت
  ISO میلادی ذخیره می‌شوند.

## اتصال به Supabase و داشبورد مدیریت

پروژه با یک دستور به بک‌اند Supabase وصل می‌شود و اسکیمای دیتابیس را می‌سازد:

```bash
npm run db:init
```

این دستور:

- اگر `SUPABASE_ACCESS_TOKEN` در `.env` تنظیم شده باشد، با آن احراز هویت کرده و
  مایگریشن‌های `supabase/migrations` را مستقیماً با
  `supabase db push --project-ref` روی پروژهٔ ابری اعمال می‌کند (شناسهٔ پروژه
  به‌صورت خودکار از `VITE_SUPABASE_URL` استخراج می‌شود).
- در غیر این صورت، پشتهٔ محلی Supabase را با Docker راه‌اندازی و اسکیما را روی آن
  اعمال می‌کند (با `SUPABASE_LOCAL=true` می‌توانید صراحتاً حالت محلی را انتخاب کنید).

### تنظیم اولیه

1. `npm install`
2. از پنل Supabase (Project Settings → API) مقادیر `URL` و `anon key` را بردارید،
   و از Account → Access Tokens یک `personal access token` بسازید؛ همه را در
   فایل `.env` قرار دهید (نمونه در `.env.example`):

   ```dotenv
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
   SUPABASE_ACCESS_TOKEN=sbp_...
   ```

3. `npm run db:init`

### جدول bookings

مایگریشن `supabase/migrations/*_initial_schema.sql` جدول `public.bookings` را
می‌سازد که هر سفارش فروخته‌شده (نام، نام خانوادگی، موبایل، کد بلیت، تعداد،
کد دانشجویی، تاریخ/سانس و مبلغ) را نگه می‌دارد. قیمت‌ها سمت سرور با یک trigger
دوباره محاسبه می‌شوند (به مبلغ کلاینت اعتماد نمی‌شود) — ثابت‌های قیمت در آن
trigger باید با `src/config/pricing.ts` هماهنگ بمانند.

امنیت (RLS): عموم (`anon`) فقط می‌تواند رکورد بسازد؛ خواندن بلیت‌ها فقط برای
`authenticated` (مدیر واردشده) مجاز است.

### داشبورد مدیریت

در آدرس `#/admin` (یا از لینک «ورود مدیر» در فوتر) باز می‌شود. برای مشاهدهٔ
بلیت‌های فروخته‌شده باید با ایمیل/رمز عبور Supabase Auth وارد شوید:

- در پنل Supabase یک کاربر با Authentication → Users → Add user بسازید.
- در Authentication → Providers، ثبت‌نام عمومی (Email) را غیرفعال کنید تا فقط
  همان حساب مدیریت بتواند وارد شود.
- داشبورد شامل جستجوی زنده روی نام، نام خانوادگی، کد بلیت، موبایل و کد دانشجویی
  و آمار (تعداد بلیت، درآمد کل، سفارش‌های دانشجویی) است.

### حالت نمایشی

اگر `.env` تنظیم نشده باشد، ثبت سفارش همچنان در حالت نمایشی (Demo) کار می‌کند:
شمارهٔ رزرو با پیشوند `DEMO-` صادر شده و روی بلیت صراحتاً نوشته می‌شود که هیچ
پرداخت یا رزرو واقعی انجام نشده است. برای حالت واقعی، `.env` را پر کنید و
`npm run db:init` را اجرا کنید.

## پرداخت کارت به کارت

پرداخت به‌صورت دستی (کارت به کارت) انجام می‌شود؛ خبری از درگاه آنلاین نیست:

1. خریدار مبلغ را به کارتِ معرفی‌شده واریز می‌کند. شمارهٔ کارت و نام صاحب‌کارت در
   `src/config/payment.ts` تنظیم می‌شود و در «خلاصهٔ سفارش» به خریدار نشان داده می‌شود.
2. خریدار تصویر رسید واریز (اسکرین‌شات) را در فرم رزرو بارگذاری می‌کند.
3. رسید در باکتِ خصوصی `receipts` در Supabase Storage ذخیره می‌شود (`receipt_path`).
4. سفارش با وضعیت `pending` ثبت می‌شود و در داشبورد مدیریت، تصویر رسید کنار
   اطلاعات خریدار نمایش داده می‌شود؛ مدیر با دکمهٔ «تأیید پرداخت» آن را `paid` می‌کند.

> مبلغ سمت سرور با trigger دوباره محاسبه می‌شود؛ کلاینت مبلغ را تعیین نمی‌کند.
> شمارهٔ کارت گیرنده را در `src/config/payment.ts` با مقدار واقعی جایگزین کنید.

«چاپ یا ذخیرهٔ PDF» از چاپگر مرورگر استفاده می‌کند؛ استایل‌های چاپ طوری تنظیم شده‌اند که فقط
بلیت (با فونت‌های فارسی و راست‌به‌چپ) چاپ شود و از همان مسیر می‌توان خروجی PDF گرفت.

## نکات فنی

- `lang="fa"` و `dir="rtl"` روی سند، و استفاده از ویژگی‌های منطقی CSS (`inset-inline-start`، …) در همهٔ استایل‌ها.
- اعداد فارسی برای نمایش؛ شماره موبایل و شناسه‌ها LTR و نرمال‌شده (`۰۹xxxxxxxxx`).
- انیمیشن‌ها `prefers-reduced-motion` را رعایت می‌کنند؛ نشانگر سفارشی فقط روی دسکتاپ فعال است.
- دسترس‌پذیری: برچسب‌های فرم، `aria-invalid`/`aria-describedby` برای خطاها، لایت‌باکس با `role="dialog"` و
  مدیریت صفحه‌کلید (Escape و جهت‌ها)، منوی موبایل با `aria-expanded`، و لینک پرش.
