# پردهٔ خاموش — وب‌سایت نمایش و رزرو بلیت

وب‌سایت تک‌صفحه‌ای و کاملاً راست‌به‌چپ (فارسی) برای معرفی یک اجرای صحنه‌ای و صدور بلیت دیجیتال، ساخته‌شده با **React + TypeScript + Vite** و CSS دست‌نویس (بدون فریم‌ورک UI).

## اجرا

```bash
npm install
npm run dev      # محیط توسعه — http://localhost:5173
npm run build    # خروجی production در dist/
npm run preview  # سرو کردن خروجی build
npx tsx scripts/smoke.ts   # آزمون منطق اعتبارسنجی، قیمت‌گذاری و تاریخ‌ها
```

## سفارشی‌سازی

| چه چیزی                                  | کجا                                       |
| ---------------------------------------- | ------------------------------------------ |
| نام گروه، عنوان نمایش، متن‌ها، سالن، تماس | `src/config/theater.ts`                    |
| قیمت بلیت عادی/دانشجویی، سقف تعداد، واحد  | `src/config/pricing.ts`                    |
| تاریخ‌ها و سانس‌های اجرا                  | `src/data/performances.ts`                 |
| عوامل و بازیگران                         | `src/data/cast.ts`                         |
| تصاویر (پوستر، صحنه، گالری، پرتره‌ها)     | `public/images/` — فهرست در `public/images/README.md` |

- **تاریخ اجراها** به‌صورت خودکار از روی تقویم هفتگی در `performances.ts` ساخته می‌شوند
  (پنجشنبه و جمعه، ۴ هفته، دو سانس) تا هیچ‌وقت تاریخ گذشته نمایش داده نشود؛ برای تاریخ‌های ثابت،
  آرایهٔ `performances` را دستی مقداردهی کنید (`dateISO: 'YYYY-MM-DD'`).
- تاریخ‌ها با تقویم جلالی (`Intl.DateTimeFormat('fa-IR')`) نمایش داده می‌شوند ولی به‌صورت
  ISO میلادی ذخیره می‌شوند.
- اگر تصویری در `public/images` موجود نباشد، یک قاب جایگزینِ طراحی‌شده با عنوان نمایش دیده می‌شود؛
  هیچ تصویر شکسته‌ای رخ نمی‌دهد.

## حالت نمایشی (Demo Mode) و اتصال به بک‌اند

ثبت سفارش در `src/services/bookingService.ts` متمرکز است. به‌صورت پیش‌فرض `demoMode: true`
است: سفارش به‌صورت محلی شبیه‌سازی می‌شود، شمارهٔ رزرو با پیشوند `DEMO-` صادر می‌شود و روی بلیت
صراحتاً نوشته می‌شود که **هیچ پرداخت یا رزرو واقعی انجام نشده است**. برای تست حالت خطا،
`simulateFailure` را `true` کنید.

برای اتصال به سامانهٔ واقعی:

1. در `bookingService.ts` مقدار `demoMode` را `false` و `endpoint` را به API خود تغییر دهید.
2. سمت سرور حتماً دوباره: اعتبارسنجی ورودی‌ها، **بازمحاسبهٔ مبلغ** (به مبلغ کلاینت اعتماد نکنید)،
   رزرو صندلی و صدور شمارهٔ رزرو معتبر انجام شود.
3. در production، محتوای QR باید یک توکن امضاشدهٔ سمت سرور باشد، نه JSON سادهٔ فعلی.

«چاپ یا ذخیرهٔ PDF» از چاپگر مرورگر استفاده می‌کند؛ استایل‌های چاپ طوری تنظیم شده‌اند که فقط
بلیت (با فونت‌های فارسی و راست‌به‌چپ) چاپ شود و از همان مسیر می‌توان خروجی PDF گرفت.

## نکات فنی

- `lang="fa"` و `dir="rtl"` روی سند، و استفاده از ویژگی‌های منطقی CSS (`inset-inline-start`، …) در همهٔ استایل‌ها.
- اعداد فارسی برای نمایش؛ شماره موبایل و شناسه‌ها LTR و نرمال‌شده (`۰۹xxxxxxxxx`).
- انیمیشن‌ها `prefers-reduced-motion` را رعایت می‌کنند؛ نشانگر سفارشی فقط روی دسکتاپ فعال است.
- دسترس‌پذیری: برچسب‌های فرم، `aria-invalid`/`aria-describedby` برای خطاها، لایت‌باکس با `role="dialog"` و
  مدیریت صفحه‌کلید (Escape و جهت‌ها)، منوی موبایل با `aria-expanded`، و لینک پرش.
